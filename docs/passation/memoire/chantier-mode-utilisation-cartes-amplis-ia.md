**Item 3 (prise en charge amplificateurs) FAIT — commit 8d76362, 19/07/2026.** Recherche préalable (agent) sur les protocoles ampli HF pilotables PC : découverte structurante — la plupart des amplis grand public (Yaesu VL-1000, Ameritron, Tokyo Hy-Power) n'ont AUCUN protocole numérique propre, juste du band-data BCD ou une écoute passive du CAT radio ; ACOM est propriétaire non documenté (reverse-engineering fragile, écarté). Seuls 3 protocoles ont une doc officielle exploitable, lus intégralement en PDF (WebFetch échoue sur ces PDF compressés → sauver le binaire puis le relire directement avec le Read tool, qui l'OCRise correctement) :
- **Elecraft KPA500/KPA1500** : ASCII `^XX;` (GET=nom seul, SET=nom+data+`;`), ex. `^WS;`→`^WSppp sss;` (puissance W + SWR virgule implicite après le 2e chiffre), `^OS0/1;` (standby/operate), `^FL;`/`^FLC;` (défaut/clear), `^BN00-10;` (bande 160m-6m), power-on = commande BootLoader `P` seule (pas de `;`, pas de réponse) — distincte des commandes normales.
- **Icom IC-PW2/PW-1** : CI-V étendu, réutilise `civ_build_frame`/`civ_parse_frame`/`civ_is_ok` de `radiocontest_cat.py` (même trame FE FE.../FD). Cmd 15/11=Po, 15/12=SWR (bruts 0-255, décodage BCD-like identique à `get_smeter()`, PAS de conversion en unités réelles inventée — non documentée), 1A/0C=protection (00-05), 1A/0D=clear, **1A/09 = équivalent standby/operate** (PIÈGE évité : ce n'est PAS la commande 18/power qui sert d'operate — 18 est la mise sous tension globale de l'appareil), 1A/03=bande, 1C/00=TX (lecture seule). PIÈGE de parsing : cmd 0x18 n'est PAS dans la table `has_sub` de `civ_parse_frame()` (écrite pour les radios, jamais pour cet ampli) — sans conséquence pour l'ENCODAGE (positionnel, insensible à cette table) mais si un jour on parse une réponse à 0x18 il faut lire `payload` et pas `sub`.
- **SPE/Expert 1.3K/1.5K/2K-FA** : paquets binaires `SYN(0x55)×3 + CNT + DATA + CHK(somme modulo-256)`, commandes = codes touche clavier (PAS des SET directs — OPERATE **bascule** l'état, d'où la relecture du statut avant/après dans `set_operate()`). Réponse STATUS (0x90) = 19 champs CSV (`SPE_BAND_ORDER` = 160→4m par index 00-11) + CHK(2 octets) + CR LF, jamais validée par checksum (pas d'invention). Pas de commande directe de changement de bande — seulement BAND+/BAND- pas à pas, géré en lisant la bande actuelle puis en steppant le bon nombre de fois.
