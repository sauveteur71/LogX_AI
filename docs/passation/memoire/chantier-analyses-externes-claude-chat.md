Le 19/07/2026, l'utilisateur a partagé PLUSIEURS analyses venant d'une **autre conversation Claude Chat parallèle** (pas cette session), qui audite périodiquement ce même dépôt de code. Deux points importants pour toute session future :

1. **Ces analyses tournent parfois sur une version différente/antérieure du dépôt** (avant le renommage `radiocontest_*`, ou sur le repo GitHub `sauveteur71/radioaamateur-program-Contest` qui n'était qu'un instantané figé du 18 juin — voir [[chantier-mode-utilisation-cartes-amplis-ia]]). Toujours VÉRIFIER les noms de fichiers/scripts cités contre l'état réel avant d'agir (ex. `validate_definitions.py`→`radiocontest_validate.py`, `eval_extraction.py`→`radiocontest_eval.py`).
2. **Un test qui "passe chez moi" peut quand même documenter un vrai bug** si le fixture/l'environnement de la session externe diffère du mien — en particulier `calldb.json` (gitignoré, ~18854 indicatifs accumulés sur cette machine au fil des sessions) et `archives/`/`radiocontest.db` masquent des bugs réels visibles seulement sur un checkout propre / en CI. **Réflexe à avoir : simuler un environnement propre en déplaçant temporairement ces fichiers gitignorés avant de conclure qu'un bug signalé "ne se reproduit pas".**
