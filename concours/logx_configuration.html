📻 5. RADIO (PILOTAGE CAT)
Pilote le transceiver depuis l'application : QSY au clic sur un spot, bande/mode suivis automatiquement, macros CW envoyées par le keyer de la radio.
📖 Quel mode choisir pour ma radio ?
NATIF — deux familles de protocole codées en dur dans LogX AI, sans logiciel intermédiaire :
  • CI-V (Icom + Xiegu) : ? radios/récepteurs Icom + Xiegu listés ci-dessous (menu MODÈLE) — fonctionne aussi avec tout autre Icom/Xiegu récent en indiquant son adresse CI-V manuellement (menu radio → Set → CI-V Address).
  • ASCII générique (Yaesu/Kenwood/Elecraft) : commandes FA/MD/IF quasi identiques sur toute la gamme de chaque marque — ? Yaesu, ? Kenwood, ? Elecraft listés ; un modèle récent absent de la liste fonctionne généralement aussi (même famille de commandes).
TCI — protocole réseau (WebSocket) d'Expert Electronics : SunSDR2 DX/PRO/QRP, MB1, ColibriDDC/NANO, ou tout logiciel compatible TCI (ExpertSDR2/3, Log4OM, RUMlogNG, JTDX/WSJT-X « improved », SDC…). Audio et flux I/Q inclus, zéro latence — le choix des stations SDR haut de gamme et du contest.
RIGCTLD (Hamlib) — pour tout le reste : Ten-Tec, FlexRadio, anciens modèles, ou toute radio non listée en natif. Hamlib gère plus de 200 modèles (liste complète des radios supportées) — lance rigctld sur le poste relié à la radio, LogX AI s'y connecte en réseau.
FLRIG — alternative à rigctld très répandue chez les utilisateurs fldigi/Linux, souvent plus réactive que Hamlib sur certains transceivers. Active le serveur XML-RPC de flrig (Config → Xcvr Setup → XML-RPC Server, port 12345 par défaut) puis renseigne son adresse ci-dessous. Pas de keyer CW via ce mode (flrig n'expose pas de commande CW fiable en XML-RPC) — bascule en TCI ou rigctld si tu en as besoin.
Le serveur TCI doit être activé dans ExpertSDR3 (ou logiciel compatible) sur le poste relié au transceiver — pas de port série, connexion réseau directe.
IP du PC où tourne le serveur TCI (peut être un autre poste du WiFi)
50001 par défaut (ExpertSDR3) — 40001 pour l'ancien ESDR2
Lance rigctld -m <n°modèle> -r <port COM> -T 0.0.0.0 sur le PC relié à la radio (fourni avec Hamlib — n° de modèle : rigctl -l). À réserver aux marques non couvertes en mode natif (Ten-Tec, RGO, modèles anciens...).
IP du PC où tourne rigctld (peut être un autre poste du WiFi)

🎙️ KEYER VOCAL (phonie — indicatif dit automatiquement)
Équivalent phonie des macros CW : synthèse vocale hors-ligne (aucun réseau), indicatif épelé phonétiquement (Alpha, Bravo…) et reports dits chiffre par chiffre, PTT activé automatiquement le temps du message (nécessite le pilotage radio ci-dessus, natif/TCI/rigctld). Le son part vers le PÉRIPHÉRIQUE choisi ci-dessous — utilise un câble audio virtuel (ex. VB-Audio) ou une interface dédiée reliée à l'entrée micro de la radio, jamais tes haut-parleurs de suivi.

☁️ 8. MULTI-POSTE & CLOUD SYNC
🌐 RÉSEAU ADIF (N1MM / DXLog / loggers tiers)
Interopérabilité temps réel avec N1MM Logger+ et DXLog.net via leur protocole de broadcast UDP <contactinfo> (format de facto entre loggers de concours tiers).
Côté N1MM : Config → Config Ports → Broadcast Data → cocher « Contact », IP de ce PC, port 12060.
Côté DXLog : Options → Broadcast → QSOs (format « N1MM-like »), même IP/port.
Désactivé par défaut
Port broadcast N1MM/DXLog (défaut 12060)
Broadcast local, ou IP précise du PC voisin
☁️ CLOUD SYNC (multi-poste, sans compte ni service en ligne)
Combine tes QSO avec un AUTRE poste (même expédition, poste de secours...) via un dossier déjà synchronisé (Synology Drive, Dropbox, OneDrive…) — chaque poste pointant vers le MÊME dossier voit les QSO des autres. Aucun compte à créer : le « cloud », c'est l'outil de sync que tu utilises déjà. Différent de la SAUVEGARDE (instantanés à sens unique) : ici les QSO des deux côtés se combinent réellement.
« Envoi seul » : pour un poste isolé qui alimente le dossier partagé sans avoir besoin des QSO des autres
Doit être IDENTIQUE sur tous les postes qui synchronisent ensemble. Configure ce dossier en « toujours conserver sur cet appareil » (pas de fichiers à la demande/placeholder) — sinon une synchro peut ralentir en attendant un téléchargement cloud.
📡 PUBLICATION MQTT (optionnelle)
Publie 3 informations simples vers un broker MQTT LOCAL (Mosquitto...) pour un tableau de bord externe (Node-RED, Home Assistant, overlay de stream...) : logx/qso (chaque QSO loggué), logx/rig/freq (fréquence radio courante), logx/score (score du concours en cours).
Nécessite le paquet Python optionnel paho-mqtt (voir requirements.txt) — désactivé par défaut, et sans effet si le paquet n'est pas installé.
IP du broker MQTT (souvent 127.0.0.1 si Mosquitto tourne sur ce PC)
ex. « logx » → topics logx/qso, logx/rig/freq, logx/score
🔒 SÉCURITÉ D'ACCÈS
Par défaut, TOUT appareil qui charge une page du logiciel sur ce réseau obtient automatiquement les droits d'écriture (ajout de QSO, changement de configuration...) — adapté à un poste/radioclub de confiance. Définis un mot de passe ici pour exiger une connexion explicite avant d'accorder ces droits (utile si le port est exposé plus largement : routeur 4G d'expédition, invités au radioclub...).
Pas de chiffrement HTTPS ici : le mot de passe circule en clair sur le réseau local, comme tes autres identifiants déjà stockés (ON4KST, QRZ...) — cette protection empêche un accès non voulu, pas une écoute réseau active.
Définir ou modifier ce mot de passe déconnecte tous les autres appareils déjà connectés (rechargement de page ou reconnexion via /auth/login nécessaire) — voulu : sinon un accès déjà obtenu avant l'activation resterait valide indéfiniment après.

🏝️ MODE EXPÉDITION
Plusieurs postes sur le même site (un par bande, voire trois par bande en CW/SSB/FT8) loggent dans le MÊME log commun : chaque poste ouvre le LOGBOOK depuis son navigateur (même WiFi), sélectionne son opérateur, et tous les QSO arrivent ensemble. L'écran mural affiche le flux en direct sur un grand écran/projecteur, et Club Log Live diffuse chaque QSO au monde.
Saisie simplifiée pour pile-up : pas de n° de série ni locator, seulement l'indicatif et les reports (59, 55, 44…)
Nécessite les identifiants ClubLog (section QSL)
Self-spot : publie ton indicatif + ta fréquence sur le cluster. Login = ton indicatif. ⚠️ Interdit par certains règlements en single-op.
VE7CC accepte le spot avec le seul indicatif. D'autres nœuds exigent une inscription.
🖥️ OUVRIR L'ÉCRAN MURAL
Flux QSO temps réel · à afficher sur le projecteur (F11 = plein écran). Marche dans n'importe quel mode d'utilisation (concours, expédition, radioclub, ou même seul) — utile pour suivre les QSO depuis une autre pièce.
L'indicatif est toujours affiché. Le prénom n'apparaît que pour les indicatifs déjà consultés via QRZ.
Objectif de QSO TOTAL pour la session/l'événement (ex. « en route vers 10 000 QSO ») — affiche une barre de progression sur l'écran mural. Distinct de l'objectif QSO/heure de la barre de statut. 0 = pas de barre affichée.
